## 1. Problem Statement

Individuals lack a simple, real‑time view of their personal finances, leading to overspending, missed bill payments, and difficulty achieving savings goals. Existing tools are either overly complex or lack actionable insights and timely alerts.

## 2. Target Users

- Adults aged 18‑45 with regular income (salaried, freelancers, gig workers)  
- Students and young professionals who want to track discretionary spending  
- Users who prefer a lightweight, mobile‑first web app with optional dark mode  

## 3. Core Features

### Feature 1: Expense Dashboard & Transaction Log
- **User Story:** As a user, I want to view my income and expenses in a dashboard with summary totals and recent transactions so that I can quickly see my financial health.  
- **Acceptance Criteria:**
  - [ ] Show total income, total expense, and net balance for a selected period (today, week, month, custom).  
  - [ ] List recent transactions with amount, category, date, and optional note.  
  - [ ] Allow filtering by date range, transaction type (income/expense), and category.  
  - [ ] Provide a “Quick Add” button to create a new transaction inline.  
  - [ ] Layout adapts to mobile, tablet, and desktop screens.

### Feature 2: Interactive Charts & Visualizations
- **User Story:** As a user, I want to see visual charts of my spending by category and trends over time so that I can identify spending patterns.  
- **Acceptance Criteria:**
  - [ ] Pie chart displaying expense distribution by category for the selected month.  
  - [ ] Line chart showing monthly income vs. expense for the last 6 months.  
  - [ ] Hover tooltips reveal exact values and percentages.  
  - [ ] Users can switch chart types (pie, bar, line) and timeframes.  
  - [ ] Charts update instantly when filters or date ranges change.

### Feature 3: Budget Planning & Alerts
- **User Story:** As a user, I want to set budget limits per category and receive alerts when I approach or exceed them so that I can stay within my financial goals.  
- **Acceptance Criteria:**
  - [ ] Create, edit, and delete budget entries (category, amount, period: monthly/weekly).  
  - [ ] System evaluates each transaction against active budgets in real time.  
  - [ ] Display a warning banner when spending reaches 80 % of a budget.  
  - [ ] Show an alert (in‑app notification) when spending exceeds the budget; optionally send an email.  
  - [ ] Users can dismiss or snooze alerts; alert history is viewable in Settings.

## 4. Technical Architecture

### Stack
- **Frontend:** React 18 + TypeScript, Vite, Tailwind CSS, Recharts (or Chart.js) for visualizations  
- **Backend:** Node.js 20 + Express, TypeScript, JWT authentication  
- **Database:** PostgreSQL (hosted on Supabase or managed AWS RDS)  
- **Auth:** JWT access token (15 min) + refresh token (7 days), password hashed with bcrypt  

### Data Model
```
Table: users
- id: UUID PK
- email: string UNIQUE
- password_hash: string
- created_at: timestamp

Table: categories
- id: UUID PK
- name: string
- type: ENUM('expense', 'income')
- user_id: UUID FK → users.id

Table: transactions
- id: UUID PK
- user_id: UUID FK → users.id
- category_id: UUID FK → categories.id
- amount: decimal(12,2)
- date: date
- description: text
- created_at: timestamp

Table: budgets
- id: UUID PK
- user_id: UUID FK → users.id
- category_id: UUID FK → categories.id
- amount: decimal(12,2)
- period: ENUM('monthly', 'weekly')
- start_date: date
- end_date: date
```

### API Endpoints
```
POST   /api/auth/register
POST   /api/auth/login
POST   /api/auth/logout
POST   /api/auth/refresh
GET    /api/users/me
GET    /api/transactions
POST   /api/transactions
PUT    /api/transactions/:id
DELETE /api/transactions/:id
GET    /api/budgets
POST   /api/budgets
PUT    /api/budgets/:id
DELETE /api/budgets/:id
GET    /api/reports/summary?start=&end=
GET    /api/reports/chart?type=pie|line&start=&end=
```

## 5. UI/UX Requirements

### Pages
1. **Landing Page** – Brief value proposition, featured screenshots, CTA for sign‑up / login.  
2. **Dashboard** – Summary cards (income, expense, net), recent transactions list, Quick Add button, charts section.  
3. **Settings** – Profile management, password change, currency & timezone preferences, budget management, notification preferences, data export / delete account.

### Design Constraints
- Mobile‑first responsive design (breakpoints: 320px, 768px, 1024px)  
- Dark / light mode toggle persisting via `localStorage`  
- WCAG 2.1 AA compliance: sufficient contrast, keyboard navigable controls, ARIA labels for interactive elements  

## 6. Security Requirements

- [ ] Input validation on all endpoints (using zod or Joi)  
- [ ] Rate limiting (e.g., 100 requests/IP/15 min)  
- [ ] CORS configured to trusted origins only  
- [ ] Secrets (DB URL, JWT keys) stored in environment variables, never in code  
- [ ] Authentication middleware protecting `/api/users/*`, `/api/transactions/*`, `/api/budgets/*`, `/api/reports/*`
