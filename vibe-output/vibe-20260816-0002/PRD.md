## 1. Problem Statement

Professionals, freelancers, and small teams often juggle tasks across disparate tools (email, sticky notes, separate apps), causing missed deadlines, duplicated effort, and low visibility into workload. Existing task managers either overload users with features or lack a secure, unified dashboard that provides quick insights into progress and upcoming work.

## 2. Target Users

- Individual freelancers managing client projects  
- Small teams (2‑10 members) needing a simple, secure way to assign and track tasks  
- Professionals who value privacy and want a lightweight tool with login protection and a clear dashboard overview  

## 3. Core Features

### Feature 1: User Authentication
- **User Story:** As a user, I want to securely sign up, log in, and log out so that my task data is private and accessible only to me.
- **Acceptance Criteria:**
  - [ ] Users can register with email and password (password strength validation)
  - [ ] Registered users can log in and receive JWT access & refresh tokens
  - [ ] Protected routes return 401 for unauthenticated requests
  - [ ] Password reset via email token works
  - [ ] Logout clears tokens on client and server

### Feature 2: Task CRUD Management
- **User Story:** As an authenticated user, I want to create, read, update, and delete tasks with due dates, priority, and categories so that I can organize my work effectively.
- **Acceptance Criteria:**
  - [ ] Users can create a task with title, description, due date, priority (low/medium/high), and category
  - [ ] Task list displays all tasks with filtering by status, priority, and category
  - [ ] Users can edit any field of an existing task and see changes reflected immediately
  - [ ] Users can delete a task; it is removed from the list and database
  - [ ] Validation prevents creation of tasks with missing title or invalid due date

### Feature 3: Dashboard Overview
- **User Story:** As an authenticated user, I want a dashboard showing task statistics and upcoming deadlines so that I can quickly assess my workload and plan my day.
- **Acceptance Criteria:**
  - [ ] Dashboard loads within 2 seconds after login
  - [ ] Shows total tasks, completed tasks, overdue tasks, and tasks due today
  - [ ] Displays a bar chart of tasks by priority and a line chart of tasks completed over the last 7 days
  - [ ] Upcoming tasks section lists the next 5 tasks sorted by due date
  - [ ] Dashboard updates in real-time when tasks are added, edited, or deleted (via polling or websocket)

## 4. Technical Architecture

### Stack
- **Frontend:** React 18 + TypeScript, Vite bundler, Tailwind CSS for styling
- **Backend:** Node.js 20 + Express.js, TypeScript, RESTful API
- **Database:** PostgreSQL 15 (hosted on Supabase or self-managed)
- **Auth:** JWT (access token 15 min, refresh token 7 days) with bcrypt password hashing; refresh token rotation

### Data Model
```
Table: users
- id: UUID PK
- email: VARCHAR(255) UNIQUE NOT NULL
- password_hash: VARCHAR(255) NOT NULL
- created_at: TIMESTAMP DEFAULT now()
- updated_at: TIMESTAMP DEFAULT now()

Table: tasks
- id: UUID PK
- user_id: UUID FK → users.id
- title: VARCHAR(200) NOT NULL
- description: TEXT
- status: VARCHAR(20) DEFAULT 'todo' (todo, in_progress, done)
- priority: VARCHAR(10) DEFAULT 'medium' (low, medium, high)
- category: VARCHAR(50)
- due_date: DATE
- created_at: TIMESTAMP DEFAULT now()
- updated_at: TIMESTAMP DEFAULT now()
```

### API Endpoints
```
POST   /api/auth/register      → {email, password}
POST   /api/auth/login         → {email, password}  → {accessToken, refreshToken}
POST   /api/auth/refresh       → {refreshToken}     → {accessToken, refreshToken}
POST   /api/auth/logout        → (clear refresh token cookie)

GET    /api/tasks              → list with query filters (status, priority, category, due_date)
POST   /api/tasks              → {title, description, status, priority, category, due_date}
GET    /api/tasks/:id          → single task
PUT    /api/tasks/:id          → {title, description, status, priority, category, due_date}
DELETE /api/tasks/:id          → → 204 No Content

GET    /api/dashboard/stats    → {total, completed, overdue, dueToday, priorityCounts, weeklyCompletion}
GET    /api/dashboard/upcoming → → list of next 5 tasks sorted by due_date
```

## 5. UI/UX Requirements

### Pages
1. **Landing Page** – Public homepage with brief value proposition, feature highlights, and prominent “Sign Up” / “Log In” buttons.
2. **Dashboard** – Authenticated view showing task list (with inline edit), filter sidebar, stats cards, and charts; includes quick‑add task button.
3. **Settings** – Profile page for updating email, changing password, toggling dark mode, and managing account deletion.

### Design Constraints
- Mobile‑first responsive layout (breakpoints: 640px, 768px, 1024px)
- Dark mode support via CSS variables, respecting system preference
- Accessibility compliant with WCAG 2.1 AA (keyboard navigation, ARIA labels, sufficient contrast)

## 6. Security Requirements

- [ ] Input validation and sanitization on all API endpoints (using zod or Joi)
- [ ] Rate limiting (100 requests/IP/15 min) on auth routes
- [ ] CORS restricted to approved frontend origins
- [ ] Secrets (JWT secret, DB credentials) stored in environment variables, never in code
- [ ] Authentication middleware protects /api/tasks, /api/dashboard/* routes
- [ ] HTTPS enforced in production; secure cookies for refresh token
- [ ] Regular dependency audits (npm audit) and use of locked versions
